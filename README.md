# DeepSeek direct API vs OpenCode Go — a measured comparison

A reproducible A/B test of `api.deepseek.com/v1` (`deepseek-flash`) against the
OpenCode Go relay `opencode.ai/zen/go/v1` (`deepseek-v4.1-flash`), covering quality,
latency and cost.

**Site:** https://deepseek-vs-opencode-go.pages.dev

## Result

| | Direct API | OpenCode Go |
|---|---|---|
| Accuracy (72 tasks × 8 runs) | 98.6% | 98.8% |
| Median latency | 1.48 s | 1.89 s (+28%) |
| p90 latency | 2.74 s | 4.04 s |
| First token (stream) | 0.42 s | 0.89 s |
| Throughput (stream) | 140 tok/s | 97 tok/s |
| 58K-token prompt | 2.27 s | 5.91 s (2.6×) |
| Billed rate (internal) | $0.15 / $0.60 per 1M | same |

- **Quality: no measurable difference.** Every category's 95% CI overlaps.
- **Same weights, verified:** at `max_tokens=1` with `top_logprobs=10`, both endpoints
  return the same top-1 token on 8 of 9 prompts, with a median |Δlogprob| ≈ 1e-5.
- **The difference is the wire.** The relay adds a fixed overhead that grows with prompt
  size — that is what users perceive as "worse quality" in long sessions.

## Method

- 72 deterministic tasks in seven categories (arithmetic, logic, instruction following,
  JSON schema, code generation, tool calling, 64K context).
- Same prompt, same `max_tokens`, `temperature=0`, 8 repetitions per task → 1,152 graded
  calls, plus probes (1,176 requests total).
- Grading is programmatic: numeric equality, parsed JSON, generated code executed against
  test cases, tool-call arguments inspected. No LLM judge.
- Extra probes: 58K-token needle-in-a-haystack, 20-tool selection, logprob fingerprint,
  streaming TTFB/throughput, prefix-cache behaviour, `reasoning_effort` matrix.

## Layout

```
site/            static site (generated) — index.html, og.png, favicon.svg, data/
build.py         regenerates site/ from the raw results
harness/         benchmark scripts (task generation, runner, probes, report)
  tasks.py       task definitions + deterministic graders
  run.py         runner (threaded, JSONL output)
  hard.py        long-context and 20-tool probes
  fingerprint.py logprob comparison
  final.py       aggregates → report.md / summary.json
  widget.py      summary widget
```

## Reproduce

```bash
cp .env.example .env    # add DEEPSEEK_API_KEY and OPENCODE_GO_API_KEY
python3 harness/tasks.py
python3 harness/run.py --pilot
python3 harness/run.py --tag main_r1
python3 harness/hard.py
python3 harness/fingerprint.py
python3 harness/final.py
python3 build.py        # rebuild the site
```

Raw per-call data for the 1,152 graded calls is published in `site/data/results.jsonl`, and every graded
figure on the site is recomputed from it. The remaining measurements — the streaming speed test
(`run.py --speed`), the 58K and 20-tool probes (`hard.py`) and the logprob fingerprint (`fingerprint.py`) —
are not in that file; rerun those scripts to reproduce them. All requests carry the neutral
`User-Agent: bench-harness/1.0`.


Live at https://deepseek-vs-opencode-go.pages.dev.

## Caveats

- No long agentic runs (50+ tool calls, 150K+ context) — that is a reliability question and
  needs its own test.
- No subjective long-form writing: the suite is deterministic on purpose.
- Neither endpoint is deterministic at `temperature=0`: 31–32% of tasks varied across the
  eight repetitions, so single-sample comparisons are meaningless.
